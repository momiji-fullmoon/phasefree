# 熊本2026 インフラ初動AI（提案用デモ）

フェーズフリー型自治体防災AI実証事業（R9 事前防災対策総合推進費）の提案用デモ。熊本県南部（北緯32.17–32.90、東経130.33–130.92）を対象に、平時の管理と、令和8年熊本地震（2026-07-28 16:27、M7.1、最大震度7）の発災後対応を、同じ資産IDとデータ基盤の上で再現する。

**初期の施設ごとの被害・点検記録・土地・公共施設・敷地は合成データ。** P1で入力する職員の実施記録は、合成投入・公表資料の暫定判読と分けて保存する。実データは、橋梁の構造台帳（xROAD）、大規模盛土造成地（不動産情報ライブラリ XKT020）、地震動・公表資料・調査速報・地盤（J-SHIS/シームレス地質）・背景地図の一部に限られる（下の「データ」）。モデルの推定値は実在の施設の状態を示すものではない。

## 実行

```sh
# 1) そのまま開く（Leaflet は vendor/ に同梱。読めない場合だけ cdnjs から読む）
open index.html            # Windows: start index.html

# 2) ローカルサーバーで開く（ブラウザが file:// を制限する場合）
python -m http.server 8000  # → http://localhost:8000/
```

- 1ファイル（約1.4 MB）に、コード・背景地図・解析用データ・実台帳の埋め込みを全て含む。外部への通信はしない（Leaflet の予備読込み、および `http://` 配信時の `kumamoto_event_data/manifest.json` との索引同期を除く）。
- ローカルでは「AIに指示」タブは **簡易ルール（キーワード判定）** で動く。Claude による手順決定は claude.ai の Artifact 上でのみ動く（`window.claude.use("sample")`）。
- 動作確認：`npm i playwright && npx playwright install chromium && node tests/smoke.js`

## 主なモデル（すべて簡易・仮定つき）

- 地震動：距離減衰＋観測震度による補正。K-NET/KiK-net の3成分波形から気象庁計測震度を算出（knet.py）
- 被害の事前確率：Φ((I−θ)/0.4)。θ は種別・状態・耐震補強・建設年・液状化・断層距離で補正
- 根拠の統合：尤度比 LR(tp,fp) の対数オッズ和（独立を仮定）
- 点検計画：Floyd–Warshall の道路網＋班ごとの貪欲挿入
- 災害廃棄物：全壊×117 t＋半壊×117×b t、住家の損傷関数（閾値は公表値に合わせて後から設定）
- 洪水：河川からの距離と施設種別による概略の想定（標高・流量なし）
- 避難所アクセス：2SFCA（0/1重み、圏域15/30/45分）

## 実データの取得（tools/fetch_kumamoto_real.py）

```sh
export DPF_KEY=...        # 国土交通データプラットフォーム
export REINFOLIB_KEY=...  # 不動産情報ライブラリ
python tools/fetch_kumamoto_real.py            # 全部
python tools/fetch_kumamoto_real.py dpf        # DPF だけ（xroad / reinfolib も指定可）
```

- DPF：`dataCatalog` 全件、「熊本」を含むデータセット（熊本県施設管理DB の識別子確定用）、`rsdb_bridge`・`cals_construction`・`cals_design`・`cals_pointcloud`・`nlni_ksj-p04/p20/a27`・`rtc_2021`・`hwq_rain` を検索。レコードごとに metadata/shape・files・downloadURLs・dataURLs を数える。原ファイル（fileDownloadURLs、60秒期限）は取得しない
- xROAD：熊本県（pref=43）の橋梁・トンネル
- 不動産情報ライブラリ：XKT020・006・010・011・018・021・022・025〜029・013、XGT001 を範囲内のタイルで取得（受付ズームは自動で探索、0.25秒間隔）
- 出力 `kumamoto_real_data.zip`（応答そのまま＋manifest.json）。**APIキーは出力に含めない。**
- 未検証の残り：熊本県施設管理DB に相当するデータセットはカタログ上に未確認（「熊本」を含む11件は dimaps/psc の地震航空写真と kkd_* の道路防災施設）。`rsdb_bridge` は検索応答の totalNumber が最大10000件に見えるため範囲内6060件で記録
- 実操作確認（2026-10-16 実行、manifest.json に記録）：DPF カタログ38件。`cals_construction/design/pointcloud` は実在しないIDで計0件（カタログ実IDは `cals_fukushima_c/d` のみ）。xROAD 橋梁 全20291件を offset 3回で取得、トンネル315件。不動産情報ライブラリは全14 API で受付ズーム13/14、約0.3万タイル中エラー11件、XKT027（高潮）は範囲内0地物
- 取得結果のアプリへの組込み：枠内の橋梁台帳（xroad.py → xroadbr.min.json）と大規模盛土造成地（xkt020.py → xkt020.min.json）は組込み済み。トンネル（315件）とその他の不動産情報ライブラリ API は未接続
- 前処理コマンド：
  ```sh
  cd tools/preprocess
  python xroad.py ../../kumamoto_real_data.zip xroadbr.min.json
  python xkt020.py ../../kumamoto_real_data.zip xkt020.min.json
  ```
- 地盤・地質の付与：`python tools/preprocess/ground.py tools/preprocess/facilities_latlon.json out.json`（J-SHIS＋シームレス地質を施設座標で取得。index.html への適用は済み＝GROUND 定数）

`kumamoto_event_data/` に保存。2026-10-18の修正・再取得後は **209データファイル・229,156,944バイト（約229.2MB）**。

- **保存と再実行**：画像は元URLのシーン構造を保持。形式・サイズ・SHA-256を検証したファイルだけキャッシュ利用し、取得は一時ファイルから原子的に置換する。manifestは既存項目を保持し、取得・失敗・移行の更新ごとに原子的に保存する。グループ指定の再実行でも他グループの出典を保持する。
- **容量制限**：画像は原則7,000,000バイト、DPM MAIN PNGは20,000,000バイトの明示的な例外、その他は64,000,000バイト。Content-Lengthの事前確認と、チャンク読み込み中の上限検査を行う。EOS-4のSAR元画像6件とR2元画像1件は容量方針で除外し、sml版を保存。
- **KMZの内容**：`sentinel_asia/products/CHIBA/Uki.kmz` は画像を内蔵するGroundOverlay。`sentinel_asia/products/EOS-RS_20260729_DPM_S1/` のDPM KMZは外部KMLタイルを参照するNetworkLinkで、タイル本体のオフライン複製ではない。外部参照URLもmanifestのmetadataに記録する。DPM MAIN PNG（12,704,520バイト）も保存済み。
- **未取得7項目**：GSIの索引・斜面崩壊GeoJSON・電子基準点変動PDF2件・活断層図の5項目は直接取得で接続タイムアウト（原因未確認）。防災科研の補足ページ1項目は実在・取得方法未確認。PASCOの候補URL1項目は404で、対応ページと提供条件を要確認。余震波形本体はこのスクリプトでは取得していない。
- **来歴と集計**：`manifest.json`（schema_version 2）にURL・実サイズ・SHA-256・検証時刻・形式・波形のサンプリング周波数などを記録する。`stored`だけを取得済みとして集計し、`manual`・`skipped_size`・`error`・`invalid`・`missing`・`unattributed`を区別する。旧版で消失した掲載ページ3件の出典URLも復元した。
- **アプリへの組込み**：データ基盤タブに「発災後の実データ」節がある。出典索引223件をindex.htmlに埋込み（file:// では埋込み索引を表示）、`http://` 配信時は `kumamoto_event_data/manifest.json` を自動同期して実物の集計・出典・保存分へのリンクを表示する。AIエージェントの `event_data_index`（実データの索引）ツールからも同じ索引を参照でき、索引の表示・照合だけを行いファイルの中身の判読はしない。
- **索引の表示制約**：階層グループの完全一致で展開するため、現在の個別表示は45行・12グループ。全223項目はmanifestに記録されている。詳細は[実装仕様書の制約・仕様差異](docs/implementation-specification.md#limitations)を参照。
- **検証**：回帰テスト21件に加え、実ファイルの全サイズ・SHA-256照合、画像87件のデコード、PDF21件の解析、GeoTIFF3件の読み取り、KMZ/ZIP3件の整合性を確認。USGSだけの再実行でも通信0件で全209ファイルの出典・ハッシュ・状態を保持した。

## AIエージェント

ツール：状況確認、モード切替、データ取込み、データ取得計画、実データの索引（kumamoto_event_data の出典一覧）、点検計画、優先施設、根拠確認、防災計画、復旧計画、土地・施設・用途、洪水想定、災害廃棄物、検査の実行、画面表示、承認依頼。

- 回答は analysis-reporting の枠（問い・結論・データ・方法・確かめていないこと・承認が必要なこと）。ページが枠の有無・順序・データの版・**結論の数字がツール出力にあるか**を検査
- AI は承認・被害の確定・通行止めの判断・避難所の開設・用地の割当をしない
- 簡易ルールは言い換えや複雑な指示に弱い。Claude 経路は Artifact 上での実動作が未検証

## 防災計画・業務実行支援の統合方針（実装計画）

[統合方針](docs/phase-free-plan-integration.md)に、既存アプリへの接続点、共通データモデル、追加画面、AIツール、実装順序、完了条件を整理。

- 地域防災計画・実施マニュアルの根拠を、業務・施設・点検計画・実施記録へ結び付ける。
- 常時表示の「計画・業務」を追加し、既存の予算配分機能は「事前対策」として整理する方針。

## 分析の検査（GeoAI-master-skills）

| 検査 | スキル | 現状の結果（例） |
|---|---|---|
| 座標と距離 | 関門1 | 楕円体距離との差 最大0.54% → 支えられる |
| 較正と基準 | uncertainty-estimation, eda-and-baseline, leakage-audit | Brier 0.116（事前のみ0.146、一律0.212）。真値は合成で一部は答えが混入 → 条件つき |
| 観測の偏り | observation-bias-audit | SNSの捕捉率が人口で 0%→75%（生成時に人口比例にしたため当然） |
| データ品質 | data-quality-audit | 30%の施設が断層距離閾値±1 km 内 → 結論は市町村・路線区間まで |
| 頑健性 | robustness-analysis | 最大発生量の市町村 12/18、上位10施設の計画入り 8/9（発災後） |
| アクセス | spatial-accessibility-analysis | 取り分0の人口割合が圏域で 28%/14%/3%（発災後） |
| 塗り分け図 | thematic-mapping, areal-interpolation | 発生量と人口の順位相関0.6、区切り方で11〜17市町村のクラスが変わる |

交差検証・残差の空間自己相関・雑音の上限・因果推定は、実の真値に当てたモデルがないため見送り（理由は画面に記載）。防災計画の「想定被害の減少」は損傷関数上の差で、因果の効果ではない。

## 既知の限界

- 評価指標（候補削減率・再現率など）は合成の真値に対する値で、自治体業務での有効性・所要時間を示さない
- 損傷関数・尤度比・工期・単価は仮の値。災害廃棄物の損傷関数は公表値に合わせて後から設定（標本内の当てはめ）
- 道路網・断層線は概略。洪水想定は標高・流量を使わない
- xROAD の「判定区分」（1〜4）を健全度に読み替える仮定（並び順の保留）は出典を確認していない。措置状況は原コードのまま表示
- 復旧後の形状・点検条件を平時の台帳へ戻す処理は未実装
